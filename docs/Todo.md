# Идеи и roadmap — Folderito

Чек-лист идей и запланированных улучшений. ✅ выполненное отмечено.

## Воспроизведение

- [x] **Таймер сна** — пресеты 10/15/30/60/90 мин + своё 5–180 (слайдер и кнопка «Запустить»); живой отсчёт в шторке и чип в плеере; по истечении — пауза; закрытие удержанием 1 с
- [x] **Скорость воспроизведения 0.5x–2x** — в плеере кнопка ⚙ рядом с эквалайзером открывает «Настройки аудиокниг»: ползунок с шагом 0.05, кнопки −/+ и шкалой 0.5x/1x/2x (метка 1x на своём месте); применяется при отпускании пальца, значение хранится в DataStore и восстанавливается при старте сервиса
- [x] **Пропуск тишины** (для подкастов и аудиокниг) — переключатель на странице «Настройки аудиокниг»; реализовано штатно Media3: `player.setSkipSilenceEnabled(true)` (порог, минимальная длительность и защита от щелчков — внутри нативного аудиопроцессора), состояние в DataStore, применяется при старте
- [x] **Защита от «битых» файлов** — при сканировании библиотеки проверяется существование файла; недоступный трек приглушается в списке с пометкой «недоступен», при запуске плавно пропускается (стартовый индекс пересчитывается), а файл, исчезнувший посреди сессии, перепрыгивается сервисом по ошибке ввода-вывода
- [x] **Четкость речи** — переключатель на странице «Настройки аудиокниг»: голосовой пресет эквалайзера (−6 дБ низы, +4…+6 дБ частоты разборчивости), перекрывает и выключает эквалайзер пользователя (примечание об этом на переключателе); хранится в DataStore вместе с состоянием эквалайзера
  - [ ] Будущее усиление: компрессия DynamicsProcessing — выравнивание громкости шёпота и пиков (Android 9+), и моно-сведение для некорректных записей (реализован только Voice EQ из трёх инструментов заметки)

## Рандом и перемешивание

- [x] **Продвинутое перемешивание** — Фишер—Йетс: каждый трек играет ровно один раз, без повторов до конца списка; рядом не ставятся треки одного исполнителя, альбома и папки (жадная раскладка после тасования)
- [x] **Запоминать остановку и список рандома** между сессиями: очередь (в текущем порядке) и линейный порядок до перемешивания сохраняются в DataStore; при старте сервиса очередь восстанавливается целиком с треком и позицией — цепочка рандома продолжается; при изменении списка (треки исчезли) недостающие отбрасываются
- [x] Алгоритмы: тасование Фишера—Йетса (O(n)); «очередь исключений» не понадобилась — линейный проход перемешанного списка и так исключает повторы; перемешанный массив индексов и указатель хранит DataStore (`pb_queue`, `pb_queue_base`)
- Примечание: перемешивание — **физическое** (переставляет очередь), поэтому «Список песен» показывает реальный порядок воспроизведения; кнопка next/prev идёт по нему же

## Плейлисты

- [x] **Показ плейлистов в дереве** — плитка «Плейлисты» первой в корне в цвете стандартных музыкальных папок (как Music/Audiobooks; по решению Петра 13.10 — плитки плейлистов тоже того же цвета, отдельный бронзовый playlistGrad больше не используется); свой скан .m3u/.m3u8 через MediaStore.Files + парсер (абсолютные, относительные `./x`/`../x`, `file://` пути; битые строки и дубликаты пропускаются); тап по плитке раскрывает треки, удержание плитки 2 с играет плейлист (вибро), галочка удержанием (~0,5 с) выделяет его целиком; треки внутри пассивны, галочки как в дереве. Проверено live: тап раскрывает, выделение «Выбрано: 2 трека», удержание запускает очередь, автопереход на вторую дорожку. Ограничение v1: только UTF-8 (ANSI-кодировки старых .m3u не читаются)
- [x] Экспорт плейлистов M3U — сохранение из «Списка песен»: кнопка «Сохранить плейлист» в шапке (иконка PlaylistAdd) сохраняет показанный список (выделение, а без выделения — очередь быстрого режима); диалог с вводом имени (автофокус, Enter = сохранить); файл .m3u пишется через MediaStore.Audio.Playlists в «Music/Плейлисты» (на новых Android каталог Playlists запрещён: allowed [Music, Movies]); при совпадении имён — копия «Имя (2)»; библиотека перечитывается — плейлист сразу в дереве. Проверено live на Samsung: файл на диске, «9 плейлистов · 109 треков», копия «TestPl (2)» создана
  - [ ] Импорт сторонних форматов (WPL/XSPF), относительные пути при экспорте (`./Song.mp3`) — опция «переносимый плейлист»


## Автомобиль и Bluetooth

Сценарий: припарковался, заглушил, вернулся через 20 мин — музыка не возобновляется; play с магнитолы по BT не помогает.

- [x] Архитектура Media3 (MediaSessionService + MediaSession)
- [x] Foreground-сервис воспроизведения (`foregroundServiceType="mediaPlayback"`)
- [x] Сохранение трека и позиции (каждые 5 с + при смерти сервиса) и восстановление при старте сервиса
- [x] Аудио-фокус: ExoPlayer `handleAudioFocus` — временная потеря → пауза, возврат → продолжение
- [x] **KEYCODE_MEDIA_STOP** от магнитолы трактуется как пауза (перехват в MediaSession.Callback.onMediaButtonEvent) — сессия не разрушается, BT-возврат продолжит с того же места
- [x] **ACTION_AUDIO_BECOMING_NOISY** (отключение BT/наушников): ExoPlayer `setHandleAudioBecomingNoisy(true)` ставит паузу; трек и секунда сохраняются циклом каждые 5 с
- [x] Восстановление **всей очереди** — очередь сохраняется и восстанавливается целиком (см. «Рандом и перемешивание»)
- [x] Проверить intent-filter `MEDIA_BUTTON` у сервиса — добавлен; плюс `onPlaybackResumption`: если процесс убит, а магнитола жмёт play, сервис отдаёт сохранённые очередь/трек/позицию, и фреймворк сам запускает воспроизведение
- [x] **Защита от OEM-оптимизаций**: в настройках (если не в белом списке) строка «Батарея» открывает системный запрос `REQUEST_IGNORE_BATTERY_OPTIMIZATIONS`

## Интерфейс и поиск

- [x] **Подтверждение при очистке списка** — «Очистить всё» (шапка библиотеки и шапка списка песен) спрашивает подтверждение
- [x] **Удержание кнопок перемотки (2 с)** открывает настройки «Шага перемотки»; тап — перемотка с вибро, срабатывание удержания — с вибро; подсказка о жесте («2 с») — на странице настроек под слайдером
- [x] **Тап по уведомлению плеера** открывает приложение (session activity у MediaSession)
- [x] **Поиск: результаты группами** — «Папки» (совпадение по имени папки, схема — найденная папка схлопнута, тап разворачивает её поддерево прямо в поиске; вложенные совпадения рисуются внутри развёрнутого родителя) и «Песни» (по названию/исполнителю/альбому, интерактивные: галочка удержанием, запуск — удержание/двойной тап играет найденное с этой песни). Проверено live: «Whats» → папки WhatsApp/Media/WhatsApp Audio с вложенностью + 11 треков по альбому
- [x] **Окна-подсказки кнопок шапки** — долгий тап по «Поиск», «Свернуть все папки», «Очистить всё» открывает окно поверх UI: иконка Info, имя кнопки, описание, крестик закрытия (тезис «теперь message box»); быстрый тап работает как раньше

## Интеграции

- [x] **Tasker / MacroDroid: «включи плеер, когда подключаю наушники»** — на стороне Tasker/MacroDroid: событие «Headset Plugged» → действие «Media Control: Play». Плеер ловит медиа-кнопку даже с убитым процессом: `MediaButtonReceiver` в манифесте (broadcast ACTION_MEDIA_BUTTON) пересылает в `PlaybackService`, тот отдаёт сохранённую очередь/трек/позицию через `onPlaybackResumption` и играет. Проверено: force-stop → медиа-Play → музыка с сохранённой позиции. Ограничение: системный Force Stop на некоторых OEM блокирует и это — помогает белый список батареи (настройки → «Батарея»)
