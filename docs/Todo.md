## Воспроизведение

- [x] **Таймер сна** — пресеты 10/15/30/60/90 мин + своё 5–180 (слайдер и кнопка «Запустить»); живой отсчёт в шторке и чип в плеере; по истечении — пауза; закрытие удержанием 1 с
- [x] **Скорость воспроизведения 0.5x–2x** (для музыки и аудиокниг) — в плеере кнопка ⚙ рядом с эквалайзером открывает «Настройки аудиокниг»: ползунок с шагом 0.05, кнопки −/+ и шкалой 0.5x/1x/2x (метка 1x на своём месте); применяется при отпускании пальца, значение хранится в DataStore и восстанавливается при старте сервиса
- [x] **Пропуск тишины** (для подкастов и аудиокниг) — переключатель на странице «Настройки аудиокниг»; Media3 `player.setSkipSilenceEnabled(true)` на сервисе, состояние в DataStore, применяется при старте
Как это устроено технически?

Программный алгоритм непрерывно анализирует входящий цифровой аудиопоток и оценивает его амплитуду. Реализация функции опирается на три главных параметра:
• Порог громкости (Silence Threshold): Уровень децибел (например, ниже -40 dB), всё что тише которого алгоритм начинает считать «тишиной». Это позволяет отсекать естественный фоновый шум или шипение микрофона.
• Минимальная длительность паузы: Чтобы плеер не вырезал микропаузы между звуками внутри одного слова (что превратило бы речь в неразборчивое заикание), алгоритм реагирует только на тишину, которая длится дольше определенного времени (например, более 300–500 мс).
• Плавное затухание (Fading): Чтобы стыки между обрезанными кусками звука не создавали резких и неприятных для слуха щелчков, на краях склейки применяется быстрое (в несколько миллисекунд) уменьшение и увеличение громкости.

Рекомендация для разработки на Android (Media3 / ExoPlayer)

Если вы развиваете свой музыкальный плеер, вам не придется писать алгоритм анализа амплитуды вручную. В современной библиотеке Jetpack Media3 (ExoPlayer) эта функция уже полностью реализована на уровне нативного аудиопроцессора.
Вам достаточно включить её одной командой в конфигурации плеера:
kotlin
// Включаем автоматический пропуск тишины в ExoPlayer
player.setSkipSilenceEnabled(true)

## Рандом и перемешивание

- [x] **Продвинутое перемешивание** — Фишер—Йетс: каждый трек играет ровно один раз, без повторов до конца списка; рядом не ставятся треки одного исполнителя, альбома и папки (жадная раскладка после тасования)
- [x] **Запоминать остановку и список рандома** между сессиями: очередь (в текущем порядке) и линейный порядок до перемешивания сохраняются в DataStore; при старте сервиса очередь восстанавливается целиком с треком и позицией — цепочка рандома продолжается; при изменении списка (треки исчезли) недостающие отбрасываются
- [x] Алгоритмы: тасование Фишера—Йетса (O(n)); «очередь исключений» не понадобилась — линейный проход перемешанного списка и так исключает повторы; перемешанный массив индексов и указатель хранит DataStore (`pb_queue`, `pb_queue_base`)
- Примечание: перемешивание — **физическое** (переставляет очередь), поэтому «Список песен» показывает реальный порядок воспроизведения; кнопка next/prev идёт по нему же

## Плейлисты

- [x] **Показ плейлистов в дереве** — плитка «Плейлисты» первой в корне со своим светлым градиентом (родственный музыкальным папкам оттенок); свой скан .m3u/.m3u8 через MediaStore.Files + парсер (абсолютные, относительные `./x`/`../x`, `file://` пути; битые строки и дубликаты пропускаются); тап по плитке раскрывает треки, удержание плитки 2 с играет плейлист (вибро), галочка удержанием (~0,5 с) выделяет его целиком; треки внутри пассивны, галочки как в дереве. Проверено live: тап раскрывает, выделение «Выбрано: 2 трека», удержание запускает очередь, автопереход на вторую дорожку. Ограничение v1: только UTF-8 (ANSI-кодировки старых .m3u не читаются)
- [ ] Экспорт/импорт плейлистов M3U / M3U8 (UTF-8) — не терять подборки; сохранять плейлисты из списка песен
  - [ ] При экспорте — выбор относительных (`./Song.mp3`) или абсолютных путей: относительные не ломаются при переносе всей папки на другой телефон

## Интеграции

- [x] **Tasker / MacroDroid: «включи плеер, когда подключаю наушники»** — на стороне Tasker/MacroDroid: событие «Headset Plugged» → действие «Media Control: Play». ## Визуал плеера

- [ ] Визуализация проигрывателя: крутится пластинка и бобина, кассета, бегающие уровни, плывущая синусоида, обложка песни


Для повышения разборчивости человеческой речи (особенно в шумных условиях автомобиля) в аудиокнигах и подкастах используются три основных программных инструмента: эквалайзер речи (Voice EQ), компрессия динамического диапазона (DRC) и моно-сведение.
Реализовать это в коде вашего Android-плеера можно с помощью стандартных эффектов Android AudioFx или встроенных процессоров библиотеки Jetpack Media3 / ExoPlayer.

1. Эквалайзер для голоса (Voice EQ / Speech Enhancement)

Человеческая речь лежит в определенном частотном диапазоне. Гулкие басы магнитолы в машине или дорожный шум часто «забивают» голос. Чтобы сделать речь четкой, нужно срезать низкие частоты (гул) и приподнять средние частоты, где находятся согласные звуки.
• Диапазон 100–300 Гц (Низкие): Нужно ослабить (срезать). Это уберет бубнение, глухость и дорожный гул.
• Диапазон 1–4 кГц (Средние/Высокие): Нужно усилить. Именно здесь находятся частоты разборчивости речи и артикуляции (звуки «ц», «с», «к», «т»).
Реализация на Android через Equalizer:
kotlin
val audioSessionId = player.audioSessionId // Получаем ID сессии ExoPlayer
val equalizer = Equalizer(0, audioSessionId).apply {
    enabled = true
}

// Пример настройки 5-полосного эквалайзера под пресет "Голос":
equalizer.setBandLevel(0, -600) // 60 Гц (срез баса на 6 дБ)
equalizer.setBandLevel(1, -300) // 230 Гц (срез на 3 дБ)
equalizer.setBandLevel(2, 400)  // 910 Гц (подъем на 4 дБ)
equalizer.setBandLevel(3, 600)  // 4 кГц (подъем разборчивости на 6 дБ)
equalizer.setBandLevel(4, 200)  // 14 кГц (небольшой подъем на 2 дБ)
Используйте код с осторожностью.

2. Усиление тихих звуков (Компрессия звука / DynamicsProcessing)

Часто в аудиокнигах чтец говорит то громко, то почти шепотом. В машине из-за шума колес «шепот» становится абсолютно неразличим. Чтобы пользователю не приходилось постоянно крутить ручку громкости, применяется динамический компрессор. Он выравнивает громкость: делает громкие звуки тише, а тихие — громче.
В Android для этого идеально подходит класс DynamicsProcessing (доступен с Android 9+). В нем есть модуль AVC (Automatic Volume Control) или Limiter/Compressor.
kotlin
val dp = DynamicsProcessing(0, audioSessionId)
val config = DynamicsProcessing.Config.Builder(
    0, // Флаги конфигурации
    1, // Количество каналов (Моно/Стерео)
    true, // Использовать InputGain
    false, // Без эквалайзера до компрессии
    true,  // ВКЛЮЧИТЬ компрессор (Mbc)
    false, // Без эквалайзера после компрессии
    true   // ВКЛЮЧИТЬ лимитер (Limiter)
).build()

dp.setChannelToKey(0, config.getChannelByChannelIndex(0))
dp.enabled = true

// Настраиваем компрессор (AGC) для выравнивания речи
val mbc = dp.getMbcBandByChannelIndex(0, 0)
mbc.attackTime = 50f   // Скорость срабатывания
mbc.releaseTime = 200f // Скорость затухания
mbc.threshold = -25f   // Порог, выше которого звук сжимается
mbc.ratio = 4f         // Коэффициент сжатия
mbc.noiseGateThreshold = -50f // Чтобы не усиливать шум в паузах
Используйте код с осторожностью.
Если это кажется слишком сложным, в ExoPlayer можно использовать более простой встроенный аудиопроцессор HapticProcessor или активировать нормализацию через сторонние библиотеки аудиоэффектов.

3. Принудительное моно-сведение (Mono Downmix)

Старые аудиокниги или любительские подкасты иногда записаны некорректно: голос звучит только в левом канале, или в стерео-каналах сдвинута фаза. В машине, где динамики разнесены по салону, это превращается в кашу.
Перевод аудиопотока в Моно объединяет каналы и пускает одинаковый, плотный сигнал во все автомобильные колонки.
Реализация в ExoPlayer (Media3):
Вы можете настроить параметры вывода аудио через DefaultTrackSelector, принудительно указав моно-режим, либо создать кастомный AudioProcessor, который пересчитывает PCM-буфер (берет среднее арифметическое левого и правого каналов: (L + R) / 2).

💡 Как это упаковать для пользователя в UI плеера

Не заставляйте пользователя крутить ползунки эквалайзера. Сделайте одну кнопку-тумблер на главном экране (или в шторке плеера) с названием вроде:
• «Четкий голос» или «Автомобильный режим для книг».
При ее включении плеер должен одновременно:
1. Активировать пресет эквалайзера со срезом басов и подъемом частот 3-4 кГц.
2. Включать компрессию DynamicsProcessing для выравнивания громкости шепота.
3. Включать функцию «Пропуск тишины» (setSkipSilenceEnabled(true)), о которой мы говорили ранее.
