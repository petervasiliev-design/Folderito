# Идеи и roadmap — Folderito

Чек-лист идей и запланированных улучшений. ✅ выполненное отмечено.

## Воспроизведение

- [x] **Таймер сна** — пресеты 10/15/30/60/90 мин + своё 5–180 (слайдер и кнопка «Запустить»); живой отсчёт в шторке и чип в плеере; по истечении — пауза; закрытие удержанием 1 с
- [ ] Скорость воспроизведения 0.5x–2x (для подкастов и аудиокниг)
- [ ] Пропуск тишины (для подкастов и аудиокниг)
- [x] **Защита от «битых» файлов** — при сканировании библиотеки проверяется существование файла; недоступный трек приглушается в списке с пометкой «недоступен», при запуске плавно пропускается (стартовый индекс пересчитывается), а файл, исчезнувший посреди сессии, перепрыгивается сервисом по ошибке ввода-вывода

## Рандом и перемешивание

- [x] **Продвинутое перемешивание** — Фишер—Йетс: каждый трек играет ровно один раз, без повторов до конца списка; рядом не ставятся треки одного исполнителя, альбома и папки (жадная раскладка после тасования)
- [x] **Запоминать остановку и список рандома** между сессиями: очередь (в текущем порядке) и линейный порядок до перемешивания сохраняются в DataStore; при старте сервиса очередь восстанавливается целиком с треком и позицией — цепочка рандома продолжается; при изменении списка (треки исчезли) недостающие отбрасываются
- [x] Алгоритмы: тасование Фишера—Йетса (O(n)); «очередь исключений» не понадобилась — линейный проход перемешанного списка и так исключает повторы; перемешанный массив индексов и указатель хранит DataStore (`pb_queue`, `pb_queue_base`)
- Примечание: перемешивание — **физическое** (переставляет очередь), поэтому «Список песен» показывает реальный порядок воспроизведения; кнопка next/prev идёт по нему же

## Плейлисты

- [ ] Экспорт/импорт плейлистов M3U / M3U8 (UTF-8) — не терять подборки; сохранять плейлисты из списка песен
  - [ ] При экспорте — выбор относительных (`./Song.mp3`) или абсолютных путей: относительные не ломаются при переносе всей папки на другой телефон
  - [ ] Продумать/изучить, откуда показывать импорт

## Автомобиль и Bluetooth

Сценарий: припарковался, заглушил, вернулся через 20 мин — музыка не возобновляется; play с магнитолы по BT не помогает.

- [x] Архитектура Media3 (MediaSessionService + MediaSession)
- [x] Foreground-сервис воспроизведения (`foregroundServiceType="mediaPlayback"`)
- [x] Сохранение трека и позиции (каждые 5 с + при смерти сервиса) и восстановление при старте сервиса
- [x] Аудио-фокус: ExoPlayer `handleAudioFocus` — временная потеря → пауза, возврат → продолжение
- [x] **KEYCODE_MEDIA_STOP** от магнитолы трактуется как пауза (перехват в MediaSession.Callback.onMediaButtonEvent) — сессия не разрушается, BT-возврат продолжит с того же места
- [x] **ACTION_AUDIO_BECOMING_NOISY** (отключение BT/наушников): ExoPlayer `setHandleAudioBecomingNoisy(true)` ставит паузу; трек и секунда сохраняются циклом каждые 5 с
- [x] Восстановление **всей очереди** — очередь сохраняется и восстанавливается целиком (см. «Рандом и перемешивание»)
- [x] Проверить intent-filter `MEDIA_BUTTON` у сервиса — добавлен; плюс `onPlaybackResumption`: если процесс убит, а магнитола жмёт play, сервис отдаёт сохранённые очередь/трек/позицию, и фреймворк сам запускает воспроизведение
- [x] **Защита от OEM-оптимизаций**: в настройках (если не в белом списке) строка «Батарея» открывает системный запрос `REQUEST_IGNORE_BATTERY_OPTIMIZATIONS`
